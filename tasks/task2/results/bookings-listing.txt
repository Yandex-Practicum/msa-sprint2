Листинг бронирований двумя путями после прогона test/regress.sh
=================================================================

1) REST из монолита (старый путь, старая БД hotelio-db, без изменений с task1)

$ curl -s http://hotelio-monolith:8080/api/bookings
[
  {"id":1,"userId":"test-user-2","hotelId":"test-hotel-1","promoCode":"TESTCODE1","discountPercent":10.0,"price":90.0,"createdAt":"2026-09-20T22:44:20.688076Z"},
  {"id":2,"userId":"test-user-3","hotelId":"test-hotel-1","promoCode":null,"discountPercent":0.0,"price":80.0,"createdAt":"2026-09-20T22:44:20.688076Z"}
]

2) gRPC из booking-service (новый путь, новая БД booking-db), через grpcurl + server reflection,
   без локальной копии booking.proto:

$ docker run --rm --network hotelio-net fullstorydev/grpcurl -plaintext -d '{}' booking-service:9090 booking.BookingService/ListBookings
{
  "bookings": [
    {
      "id": "1",
      "user_id": "test-user-3",
      "hotel_id": "test-hotel-1",
      "price": 80,
      "created_at": "2026-09-20T22:44:21.468Z"
    },
    {
      "id": "2",
      "user_id": "test-user-2",
      "hotel_id": "test-hotel-1",
      "promo_code": "TESTCODE1",
      "discount_percent": 10,
      "price": 90,
      "created_at": "2026-09-20T22:44:21.571Z"
    }
  ]
}

Важно: это НЕ одни и те же две записи. В старой БД монолита (hotelio-db) — это
статичные строки из init-fixtures.sql, они лежат там ещё с task1 и больше не
меняются, потому что POST /api/bookings больше не пишет в эту таблицу.
Из-за этого совпадения цифры в обеих таблицах выглядят почти одинаково, 
и можно ошибочно подумать, что это одни и те же записи, "перетёкшие" из одной базы в другую

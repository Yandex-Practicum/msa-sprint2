# Стратегия To Be
Принято решение на первом этапе вынести микросервис booking-service. Так как выносится верхний уровень логики, было принято решение скопировать проект hotelio-monolith, удалить из него всю логику, кроме бронирования, а вызовы к другим сервисам заменить на вызовы этих сервисов из монолита по REST протоколу.

Сервис booking-history-service было принято реализовать на .Net, так данный инструмент лучше известен разработчику.

**Конечным итогом** данной фазы должно стать обслуживание всех запросов, связанных с бронированием новым сервисом **booking-service**.


# Стратегия миграции данных при запуске нового сервиса

***Шаг 1***: Параллельная работа логики бронирования в монолите и новом сервисе бронирования. Для поддержки актуальности параллельно функционирующих баз данных предполагается настройть двунаправленную синхронизацию данных таблиц Bookings базы контейнера monolith-db и booking-service-db с помощью средств репликации Postgresql.

***Шаг 2***: Полное переключение трафика бронирования на booking-service.

***Шаг 3***: Вся аналитика ведётся на основе данных в базе **сервиса истории бронирования**. База данных монолита освобождается от аналитических запросов.

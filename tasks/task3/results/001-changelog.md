# Task 3 Report

### Gateway
- Добавлено перенаправление заголовков оригинального запроса (включая `userid`) во все нижележащие подграфы через конфигурацию `RemoteGraphQLDataSource`.

### Booking-subgraph
- Реализованы обработчики запросов (резолвер `bookingsByUser`), осуществляющие реальные HTTP-вызовы по внутренней сети Docker к запущенному контейнеру монолита из Task 2 (`http://monolith:8080/api/bookings`), полностью исключая использование моков.
- Уточнена сквозная схема интеграции: запросы из подграфа поступают в монолит, который не обрабатывает их на своей стороне, а выступает в роли прокси-шлюза, перенаправляя вызов в новый выделенный микросервис `booking-service` посредством gRPC-протокола.
- Реализован ACL: добавлена строгая проверка наличия заголовка `userid` в контексте и валидация его соответствия запрашиваемому `userId` (защита от чтения чужих данных с выбросом ошибки `FORBIDDEN`).
- Добавлено описание типа `Hotel` с директивой `@key` и связующего поля `hotel` в типе `Booking` для выполнения внешнего резолва через `hotel-subgraph`.
- Добавлено перенаправление данных оригинального запроса: идентификатор `hotelId`, полученный в конечном итоге из базы данных через цепочку проксирования, передается в виде федеративного объекта связи `{ __typename: 'Hotel', id: hotelId }`.

### Hotel-subgraph
- Реализованы обработчики запросов (`__resolveReference` и `hotelsByIds`), выполняющие прямые запросы к реальному REST-эндпоинту контейнера отелей из Task 2 (`GET /api/hotels/{id}`).
- Реализован ACL и логика маппинга данных: в процессе обработки реального ответа от контейнера монолита выполняется runtime-трансформация отсутствующих или несовпадающих полей (поле `rating` из БД округляется и преобразуется в `stars`, а имя отеля динамически генерируется по маске `"Hotel " + id`).

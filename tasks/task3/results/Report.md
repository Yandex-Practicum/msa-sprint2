## 1. Реализованные изменения
- **booking-subgraph**: Реализован ACL на уровне резолвера `bookingsByUser`. Проверяется наличие заголовка `userid` и его соответствие запрошенному `userId`. При несоответствии возвращается ошибка `FORBIDDEN` / `UNAUTHENTICATED`.
- **hotel-subgraph**: Реализован паттерн DataLoader для решения проблемы N+1. Вместо отдельных запросов к БД/API для каждого отеля, резолвер `__resolveReference` собирает все `hotelId` и делает один батч-запрос через метод `getHotelsByIds`.
- **promocode-subgraph**: Выделен в отдельный сервис. С помощью директивы `@override(from: "booking")` поле `discountPercent` теперь резолвится здесь же, на основе `promoCode`.
- **apollo-gateway**: Настроен `AuthenticatedDataSource` с переопределением `willSendRequest`, чтобы заголовок `userid` из входящего запроса автоматически пробрасывался во все подграфы.

## 2. Проверка корректности
- **Успешный запрос**: При передаче заголовка `userid: "test-user-2"` данные возвращаются корректно, включая агрегированные данные из `hotel` и `promocode` сабграфов.
- **ACL Deny**: При отсутствии заголовка или указании чужого `userid` возвращается ошибка авторизации `FORBIDDEN`.
- **Решение N+1**: В логах `hotel-subgraph` видно, что данные для отелей запрашиваются одним вызовом `📡 Fetching X hotels in ONE query`, что подтверждает работу DataLoader.
